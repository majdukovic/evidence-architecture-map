How to read this map

This page describes how the main components of the system fit together and how they talk to each other. Every component, connection and flow step has evidence: a link to the line of code that supports it, plus a short quote from that line. The date in the header is when the code was last checked.

When the code could not confirm something, it was left out. The map is deliberately smaller than the system: it covers what a newcomer needs, not every class or job.

Reading a flow

Request: a call that waits for an answer (HTTP, gRPC, SQL and so on).
Response: the answer to an earlier request.
Async: a message on a queue or topic, or a call nobody waits for.

Use the arrow keys to move between steps. Payload examples use the real field names from the code, with made-up values; ... marks fields left out, and secrets are shown as placeholders such as <token>. A Full definition link opens the class, schema or proto that defines the payload.

Links you can share

Every component, flow and step has its own address. Use Copy link, or the address bar: #node.<id> opens a component, #flow.<id>.<step> opens a flow step and #mapflow.<id> shows a flow on the map.
